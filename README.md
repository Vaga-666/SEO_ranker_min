# SEO_ranker_min
быстрое ранжирование сайтов конкурентов

Нужно создать минимальный рабочий SEO-инструмент на Python + FastAPI для проверки гипотезы.

Цель:
Проверить, можно ли на основе реальной выдачи из браузера + анализа страниц конкурентов + AI-анализа построить свой внутренний ранжировщик и получить полезные рекомендации для доработки своей страницы.

Важно:
- Не использовать официальные поисковые API.
- Не использовать SERP API.
- Источник выдачи — только реальный браузер через Playwright.
- Не делать большой сервис. Нужен компактный, рабочий MVP.
- Не делать React/Vue frontend. Нужен простой интерфейс на Jinja2 + HTMX или Jinja2 + минимальный JS.
- Не делать авторизацию, роли, команды, Redis, Celery и прочий лишний жир.
- База — SQLite.
- Код должен быть аккуратным, простым и легко расширяемым.

Стек:
- Python 3.11+
- FastAPI
- SQLAlchemy
- SQLite
- Playwright
- BeautifulSoup4 / lxml
- Jinja2
- httpx
- OpenAI-compatible LLM API через .env

Ограничения MVP:
- Только 1 поисковик: Yandex
- Только desktop выдача
- Только 1 региональный режим на старте
- Только top-10
- Только 1 целевой URL пользователя на один запуск анализа
- Без входа в Google Search Console / Yandex Webmaster
- Без автообучения весов
- Без прокси-ротации и капча-сервисов
- Без массовых задач

Что должен делать инструмент:

1. Главная страница
Форма с полями:
- поисковая фраза
- целевой URL пользователя
- кнопка "Запустить анализ"

2. После запуска:
- через Playwright открыть Yandex в реальном браузерном контексте
- выполнить поиск по фразе
- собрать top-10 органических результатов
- сохранить:
  - позицию
  - URL
  - title
  - snippet, если есть
  - домен
- сохранить HTML выдачи и screenshot страницы выдачи

3. Для каждого результата:
- скачать страницу конкурента
- скачать целевую страницу пользователя
- извлечь:
  - title
  - meta description
  - h1
  - h2/h3
  - основной текст
  - наличие FAQ
  - наличие таблиц
  - наличие списков
  - наличие CTA
  - наличие форм
  - наличие цен
  - наличие отзывов
  - наличие контактных данных
  - количество внутренних ссылок
  - количество внешних ссылок
  - наличие schema.org-разметки
- сохранить сырые данные и извлеченные признаки в БД

4. Внутренний ранжировщик
Сделать простой scoring engine с прозрачными весами.
На старте использовать 5 слоев:

- intent_fit
- structure_fit
- semantic_coverage
- commercial_fit
- trust_fit

Считай итоговый score по формуле weighted sum.

Пример стартовых весов:
- intent_fit = 0.25
- structure_fit = 0.20
- semantic_coverage = 0.25
- commercial_fit = 0.15
- trust_fit = 0.15

Весовые коэффициенты вынести в отдельный конфиг.

5. AI-анализ
Подключить AI-агента через OpenAI-compatible API.
Использовать строго JSON-ответы.
Модель должна анализировать страницу и возвращать JSON в фиксированном формате.

Нужно 2 AI-функции:

A. SERP / intent analyzer
На вход:
- поисковая фраза
- список top-10 результатов
- краткие признаки страниц

На выход JSON:
- dominant_intent
- dominant_page_type
- required_blocks
- common_entities
- commercial_expectations
- trust_expectations

B. Page analyzer
На вход:
- поисковая фраза
- краткая сводка SERP
- извлеченные признаки страницы

На выход JSON:
- page_type
- intent_fit_score (0-100)
- structure_fit_score (0-100)
- semantic_score (0-100)
- commercial_score (0-100)
- trust_score (0-100)
- strengths[]
- weaknesses[]
- missing_blocks[]
- missing_entities[]
- recommendations_short[]

6. После анализа:
Построить внутренний рейтинг страниц по total_score.
Показать:
- реальная позиция в выдаче
- наша внутренняя позиция
- разница между ними

7. Страница результата должна содержать 4 блока:

Блок 1. Таблица top-10
Колонки:
- реальная позиция
- наша позиция
- URL
- title
- total score

Блок 2. Сравнение целевой страницы пользователя со средним top-10
Поля:
- intent fit
- structure fit
- semantic coverage
- commercial fit
- trust fit
- total score

Блок 3. Gap-анализ
Показать:
- какие блоки есть у топов, но нет у нашей страницы
- какие сущности/подтемы есть у топов, но нет у нашей страницы
- какие коммерческие сигналы не дотянуты
- какие trust-сигналы не дотянуты

Блок 4. Рекомендации
Сформировать рекомендации в 3 категориях:
- срочно исправить
- желательно добавить
- можно отложить

8. Хранение данных
Нужны таблицы:
- analysis_runs
- serp_results
- page_snapshots
- page_features
- page_scores
- recommendations

9. .env
Нужно поддержать:
- OPENAI_API_KEY
- OPENAI_BASE_URL
- OPENAI_MODEL

10. Что важно в реализации
- Код должен быть понятным и не раздутым
- Сначала сырые данные, потом признаки, потом AI, потом score
- Не смешивать парсинг, scoring и рендер
- Ошибки Playwright и парсинга обрабатывать аккуратно
- Если какая-то страница не скачалась — не падать целиком, а помечать статус
- Если LLM не ответил — показывать базовый анализ без AI

11. Что НЕ делать
- Не делать авторизацию
- Не делать многостраничный кабинет
- Не делать полноценный SPA
- Не делать асинхронную очередь воркеров
- Не делать интеграции с Search Console / Webmaster
- Не делать обучение модели
- Не делать Google на этом этапе

12. Критерии готовности
Проект считается готовым, если:
- можно ввести поисковую фразу и URL
- собирается реальный top-10 из Yandex через Playwright
- страницы анализируются
- считается внутренний score
- строится собственный рейтинг
- показывается сравнение с целевой страницей
- выводятся рекомендации
- все работает локально одной командой запуска

13. Что нужно отдать в результате
- полный исходный код проекта
- requirements.txt
- .env.example
- README.md с коротким запуском
- минимальные SQLAlchemy-модели
- рабочие шаблоны страниц
- один тестовый сценарий запуска

Делай проект как аккуратный MVP, а не как платформу на 100 человек.
Главный приоритет — быстро проверить идею на реальной выдаче и получить полезный разбор по странице пользователя.
